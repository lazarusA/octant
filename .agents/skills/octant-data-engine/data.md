# Data engine (`src/data/`)

Reference for this skill, moved from `AGENTS.md` (which keeps the rules most tasks need); update it with the code it describes.

- **Data Engine Subsystems (`src/data/`)**:
  - **Blocks Engine (`src/data/blocks/`)**: `cache.rs` (LRU memory cache), `key.rs` (`BlockCacheKey`), `loader.rs` (async background workers; `load_one_wasm` the browser's loads, through `backends/web.rs` `WebFormat`, run in a data worker, `data::worker`), `prefetch.rs` (`BlockPrefetcher`: each task holds its worker slot until it ends, so Abort, which skips queued tasks and leaves running ones to finish unread, never lets new fetches pile onto old ones; an aborted task freeing its worker sends no result but sets `take_freed`, which restarts the lookahead like a result does (`poll_block_prefetch_results`), except after the Abort button until the lookahead waits for a worker (`mute_freed`, `hear_freed`); a failed block is skipped by the lookahead for `RETRY_AFTER` (5 s, `failed_recently`) or until Play, Plot or Abort, so a block that keeps failing is never asked in a loop and playback recovers with the network; the view's own requests and detail tiles still try at once; `prefetch_task.rs` `Task`, what a task shares with it; `prefetch_tests.rs`), `request.rs` (`SliceRequest`; `data/slice_request.rs` `SliceRequest::window`/`DimensionSelection::clamp`, the one window clamp of every reader and of what the browser preloads: the start moved inside the dimension, at least one element (none along an empty dimension), a rank mismatch an error), `store.rs` (`BlockStore` trait; `variable_coordinates` reads one variable's coordinates for stores whose `inspect` leaves them out), `coord_loader.rs` (`CoordinateLoader`: a variable's coordinates read in the background, once per dataset and variable; browser Zarr/Icechunk fetch them into memory first), `summary.rs` (`VariableCacheSummary`), `progress.rs` (the status bar's fetch progress, shared by every reader: chunks planned and arrived and network bytes, from the first fetch until none runs (`BlockPrefetcher` resets it); the browser's chunk, shard and Icechunk fetches plan and count their chunks, the desktop's remote Zarr counts its reads through `zarr/counting.rs` `CountingStore` and plans each block's chunks (`plan`, `progress::plan_array`: only reads under a planned array's path count as arrived, never coordinate or metadata reads); other stores, and fetches started while aborted ones still run (`BlockPrefetcher::progress_known`, `ui/status.rs`), show "Loading..."), `memory_budget.rs` (`MemoryBudget`: downloaded data kept between loads, the web's Zarr and Icechunk chunks and shard parts and Icechunk manifests (`icechunk/wasm/manifest_cache.rs`, only those no load holds), held by `Evictable` holders against `DOWNLOAD_BUDGET` (256 MiB; each data worker against half of it, `set_shared_limit`), past which the least recently used they let go are dropped, down to 7/8 of it, and fetched again when asked for; a trim that cannot get under the limit (what is left is leased) waits for a lease release or another eighth of the limit; a dropped holder's bytes stop counting), `tests.rs`, `mod.rs`. Closing a dataset (`app/state/dataset_release.rs` `remove_dataset`, `clear_all_datasets`) drops its blocks (`BlockCache::remove_source`) and its web stores (`backends::release_stores`: the Zarr, Icechunk and GeoTIFF registries' `release`, and on the desktop the opened TIFF and Icechunk session caches, so a file or repository opened again is read anew) once no other dataset, plotted layer or staged selection reads its URL.
  - **Data workers (`src/data/worker/`)**: the browser loads blocks in a few Web Workers, so fetching, decoding and slicing never hold the page's frames, as the desktop's background pool does. `data_worker` (`src/bin/data_worker/`, built by Trunk from `index.html`'s `data-type="worker"` link, fetched when a dataset starts opening) runs `host.rs`; the page's `BlockPrefetcher` keeps deciding what to load and hands each load to `worker::load` (remote Zarr, Icechunk, GeoTIFF, local files through them, procedural, and NetCDF/HDF5/MATLAB, which only workers read; other stores load on the page). `pool.rs` (`pool/messages.rs` what the workers send): half the cores, two to four workers (`slot.rs`); a load goes to the worker its store and variable hash to, so one variable's chunks are downloaded and kept by one worker (another band or step in a chunk already fetched downloads nothing) while other variables and overlays load in parallel; the workers start when a dataset starts opening (`warm`, from `inspect_active_store`), so their download overlaps its inspection; messages wait for the worker's hello, then half of `DOWNLOAD_BUDGET` (`MemoryBudget::set_shared_limit`; a variable's chunks stay on one worker, and several fill theirs only when several variables load) is sent first; messages from an earlier start of a worker are ignored; when no worker ever said hello (an error, or none in `START_TIMEOUT_MS`), loads stay on the page for the session (`Outcome::Unavailable`, `BlockLoader::load_one_wasm` in place); a worker that stops later (a panic) fails the loads it ran and is started again on the next; one that does not start while others did passes its place's loads to the next place (`page_only`, `place_of`: the page reads no NetCDF), those already waiting for it sent there once more (`run`). `host.rs`: each store opened once per worker by inspecting it as the page does (`WebFormat::inspect`, shared with `app/data_loading.rs`; loads asking meanwhile wait for it), kept until `backends::release_stores` sends `Release` (which also evicts the worker's coordinates; while loads on the store run, their loader reads its registry by URL, so it is let go when the last ends, unless a load asks for it again first (`lifetimes.rs` `Lifetimes`, tested natively)); every `REPORT_MS` the fetch counts (`progress::totals`, added by the page with `progress::add`) and toasts reported in the worker (shown once per session by the page; a worker's OME-Zarr warnings are not reported, `ome::report_warnings`); the page's language with each load. `wire.rs` the messages (JSON) and `BlockHeader` (a block's values as a transferred `Float32Array`, its value range and coordinates as a `Float64Array`, `split`/`join`), `js.rs` the framing; `wire_tests.rs`. Local files: only the page holds them (dropped folders cannot be sent to a worker), so a worker's `local::read_all`/`read_range`/`size` ask the page (`host/page_reads.rs` `read_from_page`, `FromWorker::Read`, `in_worker`); the consolidated metadata the page builds for a local Zarr folder is kept per URL (`local/read.rs` `BUILT`, forgotten with its source, never kept for a source released during the build), so each worker's inspection walks nothing. Plan: `WORKERS_PLAN.md`.
