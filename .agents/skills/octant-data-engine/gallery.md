# Gallery (`src/gallery/`)

Reference for this skill, moved from `AGENTS.md` (which keeps the rules most tasks need); update it with the code it describes.

- **Gallery Subsystem (`src/gallery/`)**: the docs gallery's entries, then the built-in procedural ones. The gallery is the one list of remote datasets: adding one is an `.mdx` file in the octant-docs repo (`content/gallery/`), no Octant release.
  - `remote.rs`: `GALLERY_URL` (`https://ndvis.github.io/octant-docs/gallery.json`, built by octant-docs `app/gallery.json/route.ts`, version 1), fetched once at startup (`OctantApp::new` calls `fetch`; a failure, as on a desktop offline, is only logged and shown in the gallery window, never fetched again by itself) and again by the gallery's Reload button (`retry`, whose failure also shows a toast), into one shared slot (`Gallery`: `Loading`, `Ready`, `Failed`; `current()`, `generation()`, which keys the voice vocabulary). `parse` is the trust boundary: refuses another `version` or a body over 4 MB, leaves out (logged) an entry that fails to read, has no http/https/s3/gs store or repeats a key. A thumbnail that is no path on `SITE` is dropped, and a `source_page` or `license_url` of another scheme than http, https, s3 or gs (`remote`, the stores' list; never `javascript:`). Tests: `install_fixture` (`fixture.json`, four real entries; every test installs the same list), network tests `fetch_blocking`.
  - `types.rs`: `GalleryEntry` (serde from the gallery's fields: `title` -> `label`, `description` -> `subtitle`, `store`, `format`, `domain` (`Domain`: the gallery's domains, unknown ones `Other`, `Procedural` only for built-ins), `tags`, `credit`, `license`, `citation`, `source_page`, `thumbnail` (a path on `SITE`), `open` (share-link keys: the view the gallery card shows), `desktop_only` (no CORS: in the browser its card shows a "Desktop only" chip, `ui/gallery/card.rs`, and `app/sources.rs` `open_gallery_entry` explains instead of loading); fields it does not read are ignored). `link()` is what opening submits: the store, or a share link of the store and `open` (`app::share::pair`), run by `submit_or_activate_source` as a pasted link. `Format` (unknown formats read as `Other`; `Procedural` only for built-ins; `name`), `shown` (the domain and format chips picked).
  - `procedural.rs`: `procedural_entries()`, the synthetic datasets, listed whether or not the gallery loaded.
  - `tests.rs`: reading the fixture, refusing another version and bad entries, links, chips, thumbnails. `data/backends/geotiff/network_tests.rs` (`cargo test --lib geotiff_gallery_entries_open -- --ignored --nocapture`) opens every GeoTIFF gallery entry and checks each server's CORS answer matches `desktop_only`; `data/ome/network_tests.rs` every OME-Zarr one.
  - `mod.rs`: re-exports and `all_entries` (gallery then procedural, no allocation).
