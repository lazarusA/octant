# Application architecture and state (`src/app/`)

Reference for this skill, moved from `AGENTS.md` (which keeps the rules most tasks need); update it with the code it describes.

- **Application Architecture & State (`src/app/`)**:
  - **Modular State Hierarchy (`src/app/state/`)**: `app_state.rs` (`OctantApp` root struct aggregating decoupled sub-states to keep borrow access disjoint), `navigation.rs` (`NavigationState`: 2D/3D camera zoom, pan, orbit, `view_interacting`), `playback.rs` (`PlaybackState`: animation timer, FPS, looping, `current_timestep`), `plot_configs.rs` (`PlotConfigs`: `LinePlotConfig`, `VolumePlotConfig`, `MeshPlotConfig`, `PointCloudPlotConfig`, `plot_transparency`), `ui_layout.rs` (`UiLayoutState`: layout toggles, `axis_style`, `panel_positions`, `plot_as_overlay`, `reveal_layers_menu`, modal dialog states), `alpha_state.rs` (`apply_alpha_curve`, `transparency_mode`), `colormap_state.rs`, `dimension_state.rs`, `line_profile.rs`, `line_series.rs`, `dataset_activation.rs`, `active_dataset.rs`, `session.rs`, `store_kind.rs` (`StoreKind`, `is_geotiff`), `plot_type.rs` (plot type switches adapt each selection and never widen a range: entering 3D gives the stacking dimension the Z role over its selected range (one plane draws a one-slice volume), leaving 3D keeps a composite's band range).
  - **Action layer (`src/app/actions/`)**: what a spoken or typed command does, one path for every input (`VOICE_PLAN.md`). `mod.rs` `AppAction` (serde, language-neutral: `SelectVariable { path }` stages, `Plot { plot_type }` plots the staged selection through `plot_from_panel` (its Add Overlay toggle turned off first), `Play`/`Pause`/`Step`/`SetColormap`/`ResetView` act on the plot (`staging.rs`: selecting through the Variables panel's `apply_selection`, plotting, playback as its button, steps as the playback bar's, the colormap as the picker sets it), `OpenSource { source }` opens a dataset by name (`open.rs`: a landing sample, catalog entry or open dataset, `source_names.rs`, one choice per store; or an address) through `app/sources.rs` (`open_sample`, `open_catalog_entry`, shared with the pills and the catalog cards), `OpenCatalog`, `SetDim { dim, value }`/`SetRange`/`SetRole` (`dims.rs`, on the staged selection through `VariableSelection::set_index`/`set_range`, shared with the Dimensions panel's sliders, and its `apply_role_change`; the staged animated dimension moves the plot's step as the playback bar does; values are ISO dates, numbers in the coordinate's units, labels, or without coordinates the 1-based position (never a year on a time axis), matched by `coord_match.rs` against the dates `utils/units/dates.rs` `coordinate_date` reads (shared with the hover's `DimContext`; a year, month, day or hour names the earliest step within it, the latest for a range's end); a dimension is named by its own name or an axis word, `axes.rs` `axis_of` deciding what each dimension is from its coordinate's CF `axis`/`standard_name`/`units`/`positive`, its OME axis type, its name, then its selection role (a time dimension may be drawn on y), as providers name dimensions anything); layers and output (`layers.rs`): `AddOverlay` (Plot Data with Add Overlay, refused with `overlay_unavailable_for`'s reason), `SetLayerVisible`, `RemoveOverlay` (`set_layer_visible`, `remove_overlay`), `SetColormap { name, layer }` (the picker's `select_layer_colormap`) and `SetColorRange` (locked as the colorbar's range inputs lock it) on a layer named by its variable, `SetView` the heatmap's window by coordinate values (`view.rs`, share links' `view`), `Export { format }` (an extension; `jpeg` said for `jpg`) opens the export dialog on that format (its own button exports: the confirmation); plates (`plate.rs`): `OpenPlateWell { well, field }` picks a well by name (`B3`) as the plate grid does and opens its 1-based field once the well's fields are read; questions (`ask.rs`): `DescribeDataset { group }` (a dataset or group of the Variables panel's tree), `Search { text }` (sets the Variables panel's search, counting through the tree's own `filter`), `DescribeVariable { path }` (long name, units, each dimension's first and last coordinate as the hover writes them), `DescribeView` (the plotted variable, step, colormap, overlays and the variable staged; the dataset when nothing is plotted), answered as data (`outcome.rs` `Done`, `Failure`); exploring stays apart from the plot as in the UI), `dispatch` (the UI's own methods) returning `Outcome` (`Done` or `Failure`), `schema.rs` the actions as tools for a language model (one per `AppAction` variant, derived by `schemars` from the type and its doc comments, `$defs` inlined; `OctantApp::tools` lists the active dataset's variables and dimensions, the layers and plot types as arguments' `enum`s up to `MAX_ENUM`, else free text; `action_of`/`OctantApp::call_tool` turn a call into an action by the same deserialization as any JSON action), typed addresses kept as written by `text.rs` `normalize` and opened by "open <address>" (words inside an address are no verbs and no "then"), `queue.rs` `CommandQueue` (`run_utterance` queues an utterance's commands, each read against the app when its turn comes; after one that opens a dataset the rest wait for `poll_inspection` (`app/data_loading.rs`) to settle it and are dropped when it fails; an action waiting for a read (coordinates, a plate's wells; `Failure::Reading`) stays first until it arrives; a failure drops the rest; the queue runs every frame (`run_commands`, from `app/floating.rs` `show_chrome`), whether or not the voice bar is open; each item keeps its `Origin`: `Voice` commands are dropped while the bar is closed, a `Link`'s by the next link (`queue_actions`, actions already built, never read as words); a failure, or a dataset that fails to open, drops only its own origin's commands (`opening` keeps the origin); after a Plot the queue ran the rest wait for its block (`plotting`, `new_plot_pending`), so colors set next are not replaced by its arrival, while a plot started by hand holds nothing; a step staged before plotting moves the animated window to hold it (`dims.rs` `go_to_step`)) and `run_commands` (voice commands: an answer's line in the bar, its detail (`answer.rs` `done_detail`) as an info toast, failures as warning toasts except text no command was read in (said in the bar, `not_understood_line`, so speech not meant as a command fills no toasts), the Variables panel opened through `set_panel_open` for what a dataset holds and searches); `resolve.rs` `Vocabulary` (`OctantApp::vocabulary`): names found in the active dataset's tree whatever its format (variable path, path suffixes, listed name, `long_name`; its dimensions and groups), plot types in every language, colormaps by name or key, datasets to open, the open plate's wells, as `Resolved`, `Ambiguous` or `NotFound` with the closest (`among` for any list of names); `candidates.rs` the names each kind goes by; `text.rs` matching with case, spaces and punctuation aside (`T 2 M` is `t2m`), CJK as substrings; `phrases/` one table of verb phrasings and "then" words per language (`<lang>.rs`, not i18n keys: they are never drawn), `commands` reads an utterance in the language whose verbs and "then" words cover most of it (the UI language on a tie), cut at punctuation, "then" words and after "open", `named.rs` what one command names, `segment.rs` its actions (each table also names the catalog, the dataset, the months, the axes, overlays, wells and fields, and the words between a range's days, `until`), `values.rs` date parts in each language's form (month names, 年月日) and standalone numbers (a number joined to a name by `_`, `z_1000`, is neither), `dates.rs` those parts and ISO dates as ISO text (a range's dates share a year said once), `split.rs` an utterance cut into commands (never inside an address), `layer_words.rs` overlay words, export formats, a color range's numbers, a well and field, `table.rs` the `Phrases` type and each language's table, `dims.rs` the dimension and values a command names (a date alone moves time; numbers only with a dimension or "go to"; two values a range; a role letter or animating a role); `tests.rs`, `open_tests.rs`, `dims_tests.rs`, `dates_tests.rs`, `ask_tests.rs`, `layers_tests.rs`, `schema_tests.rs`, `phrases/tests.rs`, `phrases/dims_tests.rs`, `phrases/ask_tests.rs`, `phrases/layers_tests.rs`, `phrases/open_tests.rs`.
  - **Share links (`src/app/share/`)**: a readable query of the plot (`?src=https://x/a.zarr&var=t2m&axes=lon,lat&anim=time&step=2020-01-15&time=2020-01-01..2020-12-31&lat=30..60&lon=0..359.75&plot=heatmap&cmap=family:name&range=250..310&overlay=sst`) replayed as `AppAction`s through the command queue (`Origin::Link`), so a link fails as a command does, without the voice bar. `mod.rs` `parse_share` (keys applied in a fixed order: `src` (remote schemes only, `SCHEMES`, never a local path), `var`, `axes` (x, y[, z]), `anim`, dimensions (any other key, every dimension as its slider holds it, the animated one its window; `dim.<name>` for one named like a key; `a..b` a range), `step` (the plot's step, `SetDim` after the window), `plot`, `cmap`, then the base layer's composite (`composite=on|off`, `rgb` its band slots, `channels=label:rrggbb[:a..b]:curve[^k][:inv]` its ticked rows (curves always written, OMERO's defaults may differ; `none` when none is ticked; a label holding `:` or `,` written as `#n`): its `CompositeStyle` whatever the dataset, after `cmap`, which turns a composite off as the picker does; `SetComposite`, reloading as the Settings controls do) and colors (`range` for colormapped plots, locked or not; `scale=name[:param]`, `opacity`, `reverse`, `nan`/`low`/`high` as `rrggbbaa`; `SetColorStyle`) (`style.rs`, `actions/style.rs`; `style_tests.rs`, `network_tests.rs` `cargo test --lib share_links_of_composites -- --ignored` the Sentinel-2 TCI and IDR nuclei composites), `view`, `overlay` repeated; `percent-encoding` decoding), `build.rs` `OctantApp::share_link` (`can_share` allocation-free for the UI; a multiscale plot and its overlays named by level 0 with level-0 indices (`multiscale::at_base`), so the opened link picks its own level for its screen; values through `actions::value_text`, the coordinate's ISO date, label or number (its fewest decimals) that `coord_match::index_of` reads back to the same index, else `#n`, the n-th position whatever the coordinates; base the page's own address on the web, else the deployed app), `tests.rs` (parsing, a link typed as a source, a plot's link plotting the same again). Entry points: `submit_or_activate_source` (the landing and Dataset fields, and the desktop's first argument), the web page's `location.search` at startup (`state/session.rs`), and the Settings header's Share button (`ui/settings/export.rs` `copy_link_button`, a success toast holding the link). `view=x0..x1,y0..y1` is a zoomed or panned heatmap's visible window in coordinate values (`build.rs` `view_value`: `NavigationState::visible_uv`, recorded every frame by `render_canvas`, placed on level 0's grid by `detail` `Axis` (`OctantApp::plotted_axes`, shared with `detail_want`) and rounded outward to cells), replayed by `SetView` (`actions/view.rs`: each end read as `SetRange` reads it, placed back on the plotted quad, `Axis::quad_fraction`, as `NavigationState::pending_view`, which `canvas/viewport.rs` `apply_pending_view` turns into zoom and pan (`heatmap_view_for`, the window contained on a canvas of another shape, within the zoom limits) once the heatmap draws the plot it was set for, dropped if another plot shows first); only evenly drawn heatmaps (`heatmap_evenly_drawn`, as detail tiles); no level in the link: the receiver reads Auto's level and the detail tile the finest one the view needs (`share/view_tests.rs`, `canvas/viewport_tests.rs`). Not in links yet: pinned multiscale levels, line and 3D views, overlay styles, opacity curves, smooth palettes.
  - **Plot Controllers (`src/app/controllers/`)**: the `PlotController` trait (`traits.rs`: `reset_view`, `handle_drag`/`handle_pan`/`handle_zoom`/`handle_scroll`, `draws_coastlines`, `draws_categories`, `resolution_demand`, `min_zoom`), its controllers (`planar.rs` `HeatmapController` and `LineController`, `orbit.rs` `Orbit3DController` for every 3D plot), and dispatcher `controller_for(plot_type)` (`mod.rs`), keeping plot-specific canvas interaction out of the UI shell.
  - **Canvas Engine (`src/app/canvas/`)**: coordinates central viewport rendering: `viewport.rs` (`compute_viewport_uniforms`, aspect ratio fitting), `interactions.rs` (`handle_canvas_interactions`: one finger or the primary button drags (pans in 2D, orbits in 3D); two fingers (`multi_touch`, only when the gesture starts on the canvas layer) pinch to zoom about their center and pan as they move, with the first finger's pointer drag ignored (fingers never land together: a second finger within `PINCH_GRACE` (0.3 s) of the first restores the view from before the first one's drag, and once two fingers touched nothing drags until every finger lifts; `TouchGesture` in egui temp memory); secondary or middle button or Shift drags pan; the wheel (`scroll_zoom_factor`), trackpad pinches and Ctrl/Cmd+wheel (`zoom_delta`) zoom about the pointer; through `PlotController::handle_drag`/`handle_pan`/`handle_zoom`; `interactions_tests.rs` with `Harness::pinch`), `keys.rs` (`handle_canvas_keys`, after the pointer's interactions, while the canvas scope is active: arrows pan 2D plots or orbit 3D ones, Shift pans further or pans in 3D, `+`/`-` zoom, `0` resets, all through the `PlotController`; Enter starts the keyboard probe (`ui/hover/probe.rs`: a stand-in pointer the hover card reads, stepped a data cell at a time, stopped by Escape or moving the mouse); with the crop box shown the arrows move it; `keys_tests.rs`); the canvas is the stable `canvas_id()` widget and a keyboard region, `axes.rs` (`draw_canvas_axes` coordinate grid lines, ticks, labels; OME-Zarr images' y axis grows downward, `PlotAxisOptions::y_down`, and their titles carry the axis unit, `y [µm]`, `VariableInfo::dimension_unit`), `axis_cells.rs` (the cells cell ticks go on, the ones the hover snaps to: a regular heatmap's `Lattice` over its cell-edge domain, with the base layer's shown detail tile's finer cells over the part of the quad it covers (`tile_cells`, `DetailTile::uv`), an irregular grid's coordinate values when they span the axis, a line plot's samples; `axis_cells_tests.rs`), `overlays.rs` (`draw_canvas_overlays` crop box, reticles, hover pins), `mod.rs` (`render_canvas` coordinating paint pipeline, axes, overlays, and colorbar overlays).
  - **Export Lifecycle (`src/app/export_lifecycle.rs`)**: in-flight figure export processing (`process_pending_export`) capturing raster PNG/JPEG/WebP, vector SVG/PDF, or clipboard data; temporary overlays and tooltips are cleanly suppressed during capture passes.
  - **Render Pipeline (`src/app/pipeline/`)**: `aspect.rs`, `axis_info.rs`, `color.rs` (`get_color_params` from the plotted layer's `ColorStyle`), `paint.rs` (`paint_active_plot`: one `paint_layer` call per layer in `LayerStack::iter`, then coastlines; the 3D ones in `paint_coastlines.rs`), `paint_layer.rs` (`CanvasView`, per-layer paint callbacks), `paint_tiles.rs` (pyramid tiles resampled to the view before painting, into one tile buffer per layer), `shown.rs` (`shown_data`, `needs_pyramid`: what a layer's heatmap uploads), `rebuild.rs` (`rebuild_layer_pyramids` after the Resampling setting changes), `rebuild_2d.rs` (a layer gets a pyramid only when Resampling is ticked or its own data exceeds one GPU buffer, `needs_pyramid`;   - **Plotted Layers (`src/app/layers/`)**: `selection.rs` (`VariableSelection`: store, metadata and `metadata_generation`, variable, dimension roles, indices, ranges and plot type; `set_index`/`set_range` the writes the Dimensions panel's sliders make, shared with voice commands;
