# Internationalization and fonts (`src/i18n/`, `src/ui/fonts/`)

Reference for this skill, moved from `AGENTS.md` (which keeps the rules most tasks need); update it with the code it describes.

- **Internationalization (`src/i18n/`)**: every user-facing text is a typed key translated at compile time into `&'static str`. `keys/` one enum per UI area (`CommonKey`, `DatasetKey`, `VariablesKey`, `PlaybackKey`, `PlotKey`, `PlotOptionsKey`, `SettingsKey`, `ColormapKey`, `ExportKey`, `HoverKey`, `KeymapKey`, `AboutKey`, `NoticesKey`, declared with `define_keys!`, wrapped by `Key`, which `key_areas!` declares with its `From` impls and `Key::all`), `translations/<lang>/<area>.rs` one exhaustive `match` per language and area (each language's module and `text` declared by `translations/mod.rs` `language!`) (`en` canonical; others return `Option`, falling back to English), `lang.rs` `Language` (all 15 in the picker `src/ui/language_picker.rs`, saved through eframe storage in `app/state/session.rs`; until one is saved, `locale.rs` `system_language` picks the first of the system's preferred locales Octant translates (`sys-locale`: OS settings on the desktop, `navigator.languages` on the web), else English), `template.rs` `{}` placeholders filled in order by `fill` (stack buffer, per frame) or `filled` (`String`, for toasts). The language is process-wide (`set_language`, `language`), so `tr(key)` works without the app; tests never set it and use `translate(lang, key)`, or draw UI in one language with the test-only `with_language` (this thread only). Caches of translated text key on `language()`. Numbers (`number.rs`): digits stay 0-9 and thousands are never grouped; only the decimal separator follows the language (a point in English, Chinese, Japanese and Korean, a comma in the others). Full dates (`date.rs` `Date`, used by `utils/units/format.rs` for the hover, timeline, bottom bar and dimension sliders; what a time coordinate's value stands for is read once, `utils/units/dates.rs` `coordinate_date`, by the hover's `DimContext` and voice commands alike) are native in Chinese and Japanese (`2020年1月15日`) and Korean (`2020년 1월 15일`) and ISO 8601 elsewhere; compact labels (axis ticks) stay ISO; `date_chars` adds their characters to the CJK font subsets. Localize numbers on the way out: `Num(format_args!("{v:.2}"))` in a format, `number::localizing(f)` inside a `Display` impl (colorbar ticks), `localize_bytes` on a stack buffer (axis ticks, hover values), `localize_string` on a `String`; only on text that is a number with fixed symbols, never on data text, file names or copied code. egui sliders and drag values show numbers through the style formatter installed by `src/ui/number_input.rs` `install`, and each takes `.localized()` (`LocalizedInput`, parsing with `number::parse`: full-width input (`０．５`) read as ASCII, either separator in comma languages, elsewhere a comma only as a thousands separator between groups of three); `guard_tests.rs` fails on a `DragValue::new`/`Slider::new` without it. Tests: `tests.rs` (every key translated in every language, placeholder counts match English, plain text only), `guard_tests.rs` (fails on English literals handed to egui text calls or toasts in `src/ui`, `src/app`, `src/export`; extend `ALLOWED` only for text that is the same in every language). Data (variable, dimension and attribute names, units, values), colormap and family names, the dataset catalog's entries, license and attribution texts, `log::` messages and format and product names stay untranslated. Fonts (`src/ui/fonts/`): `FontEngine` adds the Chinese, Japanese and Korean fonts after egui's own as fallbacks, the UI language's first (`CjkFont::fallback_order`), rebuilding the font definitions only when the language changes or a font arrives (each rebuild bumps `fonts::generation(ctx)`, which reads `u64::MAX` in that context until egui uses them the next pass, kept per context in egui temp memory), always on the UI thread (loaders that finish elsewhere, the web fetches, call `fonts_arrived`, and the next frame's `watch_dataset` rebuilds). `cjk.rs` `CjkFont` (Noto Sans SC, JP, KR; file names, `required_chars`), `store.rs` (desktop bundles the `*-ui.otf` translation subsets; web bundles only the `*-names.otf` subsets for the picker and `web.rs` fetches the active language's `fonts/*-ui.otf`, copied next to the page by Trunk, keeping fonts out of the `.wasm`), `scan.rs` `Scripts` (the Han, kana and Hangul in a dataset's names, attributes and coordinate labels, gathered in one pass per text by `dataset_text.rs` `DatasetText`: names and attributes once per `metadata_generation`, each coordinate label array once when it arrives, told apart by identity since NetCDF shares one array between every `{variable}/{dimension}` key; `han_font` picks the font for its Han text: the UI language's, else the system language's, else kana Japanese, Hangul Korean, else Chinese), `system_provider.rs` (desktop: characters no loaded font draws come from `egui_system_font_provider`, the operating system's font fallback, after the subsets; `main.rs` turns eframe's own instance off (`system_font_fallback: false`) and `follow` installs one asked for the locale of the Han font (`han_font`: the UI language's, else the dataset's `data_first`, else the system language's; `zh-Hans`, `ja`, `ko`), replaced only when that font changes, one provider per locale shared by every context). Fonts loaded at runtime are `'static` (`store::leak`, kept for the session anyway): egui copies owned font bytes on every font rebuild, `web_slices.rs` (web: the slices of Noto Sans SC, JP and KR holding a dataset's CJK characters (`DatasetText::by_font`), fetched from `fonts/cjk/<sc|jp|kr>/` with each font's `index.bin` (`slice_index.rs` `SliceIndex`, the format shared with the slicer), added after each script's subset; requested again only when the dataset's characters or Han font change; a font's index is fetched once, requests made while it loads join it; a failed font is reported once and not retried), `FontEngine::watch_dataset` (called every frame from `app/ui.rs`; acts only when `metadata_generation`, `coordinates_revision` or the language change). Each region's font covers different Han characters, so the desktop's provider tries the other Han locales for what the Han font lacks and on the web characters a font's slice index lacks go on to the next font, `tests.rs` (each subset covers its translations; scripts, font choice and installed system fonts). After changing a CJK translation run `cargo run --features font-tools --bin subset_fonts` (`src/bin/subset_fonts/`: reads the fonts from noto-cjk pinned to a commit and verified by MD5, subsets them with `allsorts` (optional dependency behind the `font-tools` feature), fails on characters a font lacks, writes `assets/fonts/` and its `LICENSE.md` (OFL-1.1, shown under About)). The web slices come from `tools/cjk_slices`, a standalone crate (`[workspace]` of its own, so `pages.yml` builds it without compiling Octant) that includes the subset tool's `pins.rs`, `download.rs` and `subset.rs` and the app's `slice_index.rs` by path: slice 0 holds the language's common characters (GB 2312 level 1, JIS X 0208 level 1 with kana, KS X 1001 Hangul, read through `encoding_rs`), the rest follow in codepoint order; `pages.yml` runs it into `dist/fonts/cjk` after `trunk build` (for a local `trunk serve`, run `cargo run --release --manifest-path tools/cjk_slices/Cargo.toml -- dist/fonts/cjk`); `rust.yml` formats, lints and tests it.
