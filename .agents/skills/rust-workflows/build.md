# Build size and licensing

Reference for this skill, moved from `AGENTS.md` (which keeps the rules most tasks need); update it with the code it describes.

- **Build size**:
  - `[profile.release]` (desktop and `trunk build --release`) keeps full speed (`opt-level = 3`) with `lto = true`, `codegen-units = 1` and `strip = true`; do not trade speed for size. Trunk runs `wasm-opt` at `-O3` (`data-wasm-opt` in `index.html`), with `data-wasm-opt-params` enabling the WASM features rustc emits by default (bulk memory, sign extension, ...); when rustc enables a new one, `wasm-opt` fails validation and the flag must be added there. CI (`rust.yml` `wasm` job, Trunk pinned in `rust.yml` and `pages.yml`) runs `scripts/check_wasm_size.sh`, which fails when the brotli-compressed app `octant-*_bg.wasm` exceeds `.github/wasm-size-budget` (the voice worker's `voice_worker_bg.wasm` its `.github/wasm-size-budget-voice-worker`, the data worker's `data_worker_bg.wasm` its `.github/wasm-size-budget-data-worker`) (bytes, set about 8% above the measured size). Raise the budget only in a dedicated commit that explains the growth.
- **Licensing & Redistribution**:
  - Third-party notices live in `assets/licenses/THIRD_PARTY_LICENSES.md`, generated by `scripts/third_party_licenses.sh` (`cargo about generate --fail -o assets/licenses/THIRD_PARTY_LICENSES.md about.hbs`, `cargo install cargo-about --locked --features cli`, then every listed crate's `NOTICE` file appended under Notices, as Apache-2.0 asks; needs `jq`). Regenerate and commit it whenever `Cargo.lock` changes; CI fails when it is stale. `about.toml` lists the accepted (permissive) licenses and pins clarifications for crates whose license lives in files (netCDF-C, HDF5, egui's fonts): when a clarified crate updates, verify the new license file and update its checksum instead of widening `accepted`.
  - The notice files (third-party, colormaps, and the CJK fonts' `assets/fonts/LICENSE.md`) are embedded in the binary and shown under About (`src/ui/about/licenses.rs`, virtualized viewer), copied next to the web build by Trunk (`index.html`), and packaged with the desktop installers (`[package.metadata.packager]` resources in `Cargo.toml`; `.github/workflows/release.yml` `installers` builds every `cargo packager --formats all` format on macOS, Windows and Ubuntu 22.04 and runs `scripts/check_linkage.sh`, which fails when netCDF or HDF5 are linked dynamically (Windows keeps the shared Visual C++ runtime: with `crt-static`, netCDF's `#define fstat _fstat64` clashes with the static runtime's own); `workflow_dispatch` builds them without releasing).
