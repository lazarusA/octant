# Octant Agent Rules

When developing and reviewing code in this repository:

1. **Rust Quality & Checks**:
   - Adhere to idiomatic Rust (Rust 2024 edition).
   - Enforce borrow-over-clone (`&[T]` over `&Vec<T>`, `&str` over `&String`).
   - Forbid `unwrap()` in production code (use `?`, `let Some(...) = ... else`, or `f32::total_cmp`).
   - Use poison-resilient lock handling (`if let Ok(guard) = ...` or `.unwrap_or_else(|p| p.into_inner())`).
   - Always use checked arithmetic when computing multi-dimensional tensor shape volumes (`shape.iter().try_fold(...)`).
   - Run `cargo fmt --all -- --check` and `cargo clippy --all-targets -- -D warnings`.
   - For C-library/FFI test suites (e.g. NetCDF), serialize file creation with static mutex test locks to prevent concurrent non-reentrant IO collisions.
   - Build size: `[profile.release]` (desktop and `trunk build --release`) keeps full speed (`opt-level = 3`) with `lto = true`, `codegen-units = 1` and `strip = true`; do not trade speed for size. Trunk runs `wasm-opt` at `-O3` (`data-wasm-opt` in `index.html`), with `data-wasm-opt-params` enabling the WASM features rustc emits by default (bulk memory, sign extension, ...); when rustc enables a new one, `wasm-opt` fails validation and the flag must be added there. CI (`rust.yml` `wasm` job, Trunk pinned in `rust.yml` and `pages.yml`) runs `scripts/check_wasm_size.sh`, which fails when the brotli-compressed `*_bg.wasm` exceeds `.github/wasm-size-budget` (bytes, set about 8% above the measured size). Raise the budget only in a dedicated commit that explains the growth.

2. **Modular Architecture & Subsystem Layout**:
   - Follow the Open-Closed Principle (OCP): decompose monolithic modules into single-purpose submodules (< 250 lines per file, < 50 lines per function).
   - **Catalog Subsystem (`src/catalog/`)**:
     - `entries.rs`: Built-in static catalog tables (GeoTIFF, Zarr, Icechunk, Procedural).
     - `types.rs`: `CatalogEntry`, `CatalogCategoryFilter`, `CatalogProvider` trait.
     - `tests.rs`: Category filtering, projection capability, and JSON serialization tests.
     - `mod.rs`: Re-exports and `get_catalog_entries`.
   - **Data Engine Subsystems (`src/data/`)**:
     - **Blocks Engine (`src/data/blocks/`)**: `cache.rs` (LRU memory cache), `key.rs` (`BlockKey`), `loader.rs` (async background workers), `prefetch.rs` (`BlockPrefetcher`), `request.rs` (`SliceRequest`), `store.rs` (`BlockStore` trait; `variable_coordinates` reads one variable's coordinates for stores whose `inspect` leaves them out), `coord_loader.rs` (`CoordinateLoader`: a variable's coordinates read in the background, once per dataset and variable; browser Zarr/Icechunk fetch them into memory first), `summary.rs` (`BlockSummary`), `tests.rs`, `mod.rs`.

       - `coord_bounds/`: `cache.rs` (global cache keyed by `(store URL, group scope, dimension)`; a scoped lookup reads its own group before any cached one; `evict_coord_values`), `candidates.rs`, `discover.rs`, `extract.rs`, `variables.rs` (`fetch_all_dimension_coordinates_for_variables`: `{variable}/{dim}` keys per grouped variable, unscoped keys first come), `preload.rs` (`CoordPreload` and `settle_preloaded_coordinates`: WASM coordinates whose middle chunks failed keep `Endpoints`, failed endpoints are dropped), `tests.rs`, `mod.rs` (Unified coordinate boundary resolution & global cache).

Opening a Zarr or Icechunk dataset (desktop and browser) reads metadata only; a variable's coordinates are read when it is clicked or plotted (`BlockStore::variable_coordinates`, `wasm/preload.rs` `load_variable_coordinates`, `wasm/coord_paths.rs`), and a block preloads and reads coordinates only for its range-selected dimensions, `coords_tests.rs`, `coords_numeric_tests.rs`, `zstd_shim.rs`, `wasm/` (`inspect.rs`, `loader.rs`, `preload.rs`, `store.rs`, `mod.rs`), `mod.rs`.

     - **Block orientation**: `utils/grid.rs` `check_and_orient_block_grid` orients the last two dimensions (only when no latitude or longitude dimension precedes them, `grid_flips::spatial_dims_last`), deciding the flips from the whole dimensions' extents (`grid_flips::OrientHints`, filled by the Zarr and NetCDF readers) so every block of a variable, including one-row edge blocks, flips alike, and skipping the copy when nothing changes. It transposes lon-first blocks (`grid_flips::needs_transpose`, swapping names and origins whenever it transposes) and flips rows/columns north-up and west-left, recording them in `OctantBlock::flipped_dims` and reversing per-index coordinates with them. Code indexing a block in stored order goes through `src/data/block_orientation.rs`: `oriented_range` for slicing a stored-order window, `slab_destination` for placing a block's 3D slab (mirrored across the volume along flipped dimensions; `src/app/block_loading/volume_slab.rs`).
     - **Dimension coordinates (`src/data/metadata/coord_values.rs`)**: `DatasetMetadata.dimension_coordinates` holds `CoordValues` (`Regular` start/step for evenly spaced axes of any length, `Values(Arc<[f64]>)`, `Labels(Arc<[String]>)`, `Endpoints` when only the ends were read), so clones share the values; `SpacingCheck` detects even spacing value by value (with `f32` rounding for `f32` sources). Read coordinates by index (`get`, `number_for`, `range_bounds`); never iterate them in per-frame UI code. Caches of data derived from loaded metadata key on `VariableSelection::metadata_generation` (of `OctantApp::selected` and of the plotted layer's selection, `OctantApp::plotted()`; carried along whenever metadata is copied or staged) and `coordinates_revision` (bumped when a variable's coordinates arrive and are merged by `app/block_loading/coordinates.rs`), never on the metadata's address, which stays the same across datasets. Coordinates may be missing until they arrive: read them through `get_dim_coords` and fall back to indices.
     - Store tensor values in `Arc<[f32]>` for $O(1)$ zero-copy sharing between cache and render pipelines.
   - **Colormaps (`src/utils/colormap/`)**: one source of truth for CPU and GPU. Every colormap is a 256-entry RGBA8 `Lut` (`lut.rs` resampling, Oklab `smooth`, `bake` for colorgrad gradients & `sample_lut`, matching WGSL `sample_colormap` exactly: stepped categorical rows use the nearest texel (`registry::is_stepped` on the CPU, the `nearest` uniform on the GPU), all others blend two texels); `catalog.rs` decodes the bundled `assets/colormaps/colormaps.bin` (`format.rs` shared binary layout, `kind.rs` `ColormapKind`); `registry.rs` holds built-in + custom maps (ids are atlas rows, stable `"family:name"` keys, `generation()` for cache refresh, `COLORMAP_RGB_COMPOSITE` sentinel; rows after `len()` are Oklab smooth twins of categorical palettes with at most `SMOOTH_MAX_COLORS` colors, resolved with `smooth_variant`, then one opacity curve row per curve key (a layer's `LayerId::key`) in key order (`curve_rows.rs`, re-exported by `registry`: `set_alpha_curve(key, lut)`, `alpha_row(key)`, `curve_alpha(key, t)`, `row_curve_alpha(row, t)`; not colormap rows, so `is_row` excludes them), so `rows()` sizes the atlases while `len()` counts colormaps); `custom.rs` builds user maps with `colorgrad`; `alpha.rs` opacity curves over the data position (values or `position:alpha` stops, linear or step, `PRESETS`) baked into the alpha channel of one LUT; `eval.rs`/`scale.rs` CPU evaluation (`registry::sample`/`sample_row` sample atlas rows; alpha is the uniform `opacity` times the layer's curve (`ColorStyle::alpha_at`, `registry::row_curve_alpha` for a uniform's `alpha_row`), matching WGSL `plot_alpha`, indexed by the data position before reversal); `tests.rs`, `catalog_tests.rs`, `smooth_tests.rs`, `alpha_tests.rs`. Tests that add or remove custom maps or depend on row ids take `registry::test_lock()`. Never hand-write colormap formulas in Rust or WGSL: add maps to the catalog or registry instead.
     - Regenerate the catalog with `cargo run --bin fetch_colormaps` (`src/bin/fetch_colormaps/`: `families/` curated families read from their original projects, every fixed download a `Remote` (URL + MD5) pinned to a commit in `urls.rs`/`palette_urls.rs` where the host allows it, live unpinnable hosts in `live.rs` guarded by MD5 alone, per-map files listed from a verified index read through `Fetcher::pinned_text` (commit-pinned URL, no MD5), split into `classic.rs` Matplotlib-derived, `scientific.rs`, `palettes.rs`, `picks.rs` name tables and `notices.rs` attribution texts; `sources/` one parser per upstream format (`mod.rs` dispatch grouped into Python, text and structured sources): `pylit.rs`/`pylit_parser.rs` Python literals, `matplotlib.rs` exact port of Matplotlib's 256-entry LUT sampling (segment tables, cubehelix, `from_list`, listed) with `mpl_functions.rs` (`gfunc`, flag/prism, gist, each checked against its upstream source lines), `julia.rs` ColorSchemes.jl data (Paintings only), `python.rs`, `text.rs` (tables, C arrays, CSS, R lists, YAML, CARTO TS), `json.rs`, `packages.rs` multi-file sources (colorcet, cmocean, CMasher, Crameri), `zip.rs` CRC-checked reader for Crameri's Zenodo archive (cached in `target/fetch_colormaps/<md5>-<name>`); `fetch.rs` MD5-verified downloads & license texts, failing on empty families and duplicate names; `classify.rs` kind rules & lightness heuristic). Only add families whose license is in `COMPATIBLE_LICENSES` (CC0, MIT, BSD-3-Clause, Apache-2.0, Matplotlib, CC-BY-4.0, and `LicenseRef-Public-Domain-Facts` for short unlicensed color lists; the converter refuses others, e.g. GPL), always read data and license texts from the original project (sole exception: the Paintings family, created by and read from ColorSchemes.jl), credit attribution licenses such as CC-BY-4.0 (creator, license link, modifications) in `LICENSES.md` and the About credits, and keep `assets/colormaps/LICENSES.md` in sync.

     - Colormapped pipelines bind the shared colormap atlas (`colormap_atlas.rs`, 256×K `Rgba8Unorm`, stored in egui-wgpu `CallbackResources`) at `@group(1)`: add `colormap_atlas::bind_group_layout(device)` to the pipeline layout, call `colormap_atlas::prepare(device, queue, callback_resources)` in the callback's `prepare` (uploads rows changed anywhere in the frame) and `colormap_atlas::bind(rpass, callback_resources)` in `paint`. Sample colors in WGSL with `sample_plot_colormap(color, t)` (honors `reverse`).
     - **Volume raymarcher (`src/plots/volume/`)**: voxels live in 3D textures (`textures.rs`: `R32Float` values, `Rgba8Unorm` for RGB composites, `R8Unorm` validity; uploads cover whole Z planes plus one neighbor plane each side; chunks without missing voxels upload straight from the volume, others are encoded in parallel by `encode.rs` (missing voxels take their valid 26-neighbor average so trilinear filtering stays smooth; the filtered validity's 0.5 level is the missing-data boundary). Rays step `quality` samples per voxel (at most `MAX_SAMPLES` = 384 per ray, `main.wgsl`) with interleaved-gradient jitter. Colors come from the shared colormap atlas (`@group(1)`, bound in the raymarch pass via `colormap_atlas::bind_group`). DVR (mode 0, `dvr.wgsl`) samples trilinearly; its opacity is `dvr_opacity` (`t^(1/Density)` of the scale position, floored at 0.01; Density default 3) per `REFERENCE_STEP`, corrected for the actual step so it is independent of quality. `pipeline.rs` builds two shader variants from `src/plots/shaders/volume/`: hardware filtering when the device has `FLOAT32_FILTERABLE` (requested when available by `src/plots/device.rs`), else an exact eight-tap filter. Ring-buffer shifts use a Repeat sampler with logical coordinates clamped to edge texel centers. DVR shading (`shading.wgsl`) uses world-space tetrahedral gradients (stencils kept off the box faces), viewer-facing normals and a camera-following headlight; opaque hits are bisected, and a volume cut open at the entry face shades with the face normal. Transparent DVR lighting (`lighting` uniform, "Lighting" checkbox, off by default) blends diffuse-lit color in by gradient strength and never changes opacity. Modes 1-7 (`classic.wgsl`, `projections.wgsl`, `rgba.wgsl`) keep the original algorithms on nearest voxels with straight alpha, premultiplied in `fs_main`; change them only on request. Output is dithered and premultiplied      - Rendering goes through a cached offscreen frame (`frame.rs` `FrameKey`: uniforms, data upload version, colormap generation, size; `render.rs`): the raymarch reruns only when the key changes and is blitted into egui's pass otherwise, at half resolution while view_interacting (drag or zoom; `app.nav.view_interacting`). 3. **Zero-Allocation UI & Render Loop Rules**:
   - In immediate-mode UI loops, prefer zero-allocation tuple salts `("salt", id)` over heap-allocating `format!(...)`.
   - Never format tick labels or build dynamic `Vec`s per frame: format into stack buffers (`[u8; 32]`, `stack_str`) and stack arrays (e.g. `[TickMark; 7]`), or cache formatted labels until their inputs change (`ui::temp_cache::cached`). egui's own copy of the text when laying it out (`painter.text`, `layout_no_wrap`) is unavoidable and fine.
   - Never keep text galleys (`Arc<Galley>`) across frames: egui rebuilds its fonts and glyph atlas when the text options change (switching dark/light mode) or the atlas fills up, and an old galley then draws stale atlas texels as scrambled text. Lay text out every frame through egui (its galley cache makes unchanged text a hash lookup); within one frame, laying out once and reusing the galley is fine.
   - Use zero-allocation case-insensitive ASCII searches (`contains_ascii_case_insensitive`) from `crate::data::coordinates::naming` for dimension and coordinate parsing.
   - All custom canvas overlays and floating toolbars must dynamically adapt to dark and light visual themes (`ui.visuals().dark_mode`).
   - Transient UI overlays (crop handles, grids, tooltips) must be suppressed during export capture passes (`if app.pending_export.is_none()`).
   - User-facing failures, warnings and results go through `OctantApp::notify` / `push_notice` (with the app) or `crate::ui::toast::report` (renderers, backends, background threads), which show a canvas toast and log it; never only `status_message` (not displayed) or the log. Keep internal fallbacks and per-chunk failures that already surface as one higher-level error log-only.
   - **No raw emojis or unicode glyphs**: Do not use font-dependent emojis or unicode symbols in UI widgets, buttons, labels, logs, or status messages. Use procedural vector icons from `crate::ui::icons::Icon` via `UiIconExt` (`icon`, `icon_toned`, `icon_button`, `icon_label`), `ToolbarButton` for frameless toolbar buttons, or `Icon::paint` for decorative art. Size icons only with `IconSize` (`Xs` 12, `Sm` 14, `Md` 18, `Lg` 24) and color them with theme-adaptive `IconTone`s instead of hard-coded `Color32`s. Close and clear-field buttons always use `ui.close_button(hover)` (frameless `Icon::Cross`, no label); close buttons sit in the top-right corner of their panel or window, in place of egui's built-in title-bar close. If a new visual symbol is needed, define it as a procedural vector icon in `src/ui/icons/` with dark/light theme support.
